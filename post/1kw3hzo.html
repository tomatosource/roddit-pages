Input Request - Make ‘Shift’ usable when WASD is the Input Method for skill inputs

Problem:

When using WASD as the primary input method in POE2, I cannot rebind ‘SHIFT’ to any of the “use bound skill” bindings without it breaking stash UI interactions in the game.

Context:

  • SHIFT is currently mapped to “Attack in Place” as the default binding.
    • When this is used, it doesn’t close any of the windows
  • SHIFT is also currently mapped to “Compare Item Descriptions” which works when inventory UI is open
  • SHIFT is used to stack / unstack items in player and stash inventory and works as expected despite it also being bound to two other functionalities as mentioned above.
  • When SHIFT is rebound to anything else, it closes the stash windows because of the action it is bound to
  • Either changing how SHIFT functions when stash UI is up OR allowing to rebind “SHIFT” for other interactions in the UI, inventory management, etc would allow for an easily usable button for one of the “use bound skill” bindings.
    • In my case, wanted to replace the “T” binding to make parrying / blocking a more natural feeling input

Expected / Preferred Behavior:

  • If SHIFT is bound to a “bound skill”
  • And the stash UI is up
  • When SHIFT is pressed, it doesn’t close the windows to perform the bound skill
  • Instead it allows the user to stack/unstack items and compare item descriptions as intended

OR

  • Allow the stacking / unstacking functionality to be rebound to a different key so that shift can be used as a viable button input

EDIT:
I would also like to point out that binding Caps Lock and other Mouse buttons (besides M4 and M5) would be super helpful as well.
